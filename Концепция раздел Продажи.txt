Подробное описание раздела "Продажи"
Общая концепция
Раздел "Продажи" - это центральный hub для управления всем циклом работы с клиентом от первого контакта до подписания договора. Раздел строится вокруг воронки продаж с визуализацией Kanban и обеспечивает бесшовную интеграцию с разделами "Проекты" (для смет) и "Объекты" (для производства работ).[bitrix24]​
Архитектура данных
Сущность "Сделка" (Deal)
Карточка сделки содержит 5 блоков информации:
Блок 1: Контактная информация клиента
* ФИО клиента (обязательное поле, текст)
* Телефон (+7 формат с маской, обязательное, с кнопкой быстрого звонка)
* Email (опционально, с валидацией)
* Мессенджеры (Telegram handle, WhatsApp) с кнопками быстрой связи
* Источник заявки (выпадающий список: Сайт, Телеграм, Телефония, Email, Социальные сети, Рекомендация, Повторное обращение, Другое)
* Дата создания (автоматическая)
* Ответственный менеджер (выбор из списка пользователей с ролью "manager")
* Температура лида (визуальный индикатор: 🔥 Горячий / 🌡️ Теплый / ❄️ Холодный)
Блок 2: Информация об объекте
* Адрес объекта (текст с возможностью выбора из Яндекс.Карт)
* Подъезд, этаж, квартира/офис (отдельные поля)
* Домофон код (для удобства замерщика)
* Тип строения (выбор: Новостройка, Вторичка, Частный дом, Коммерческое помещение)
* Площадь помещения (число, м²)
* Количество комнат (1, 2, 3, 4+, Студия)
* Тип санузла (Раздельный, Совмещенный, 2 санузла, Без санузла)
* Высота потолков (стандартная 2.7м / другая)
* Наличие лифта (да/нет, важно для доставки материалов)
Блок 3: Параметры ремонта
* Тип ремонта (выбор: Дизайнерский, Капитальный, Косметический, Частичный)
* Состояние объекта (Черновая отделка, Вторичка со старым ремонтом, После демонтажа, Частично отремонтирован)
* Бюджет клиента (число, ₽, диапазон "от-до")
* Требуется дизайн-проект (чекбокс да/нет)
* Помещения для ремонта (мультивыбор: Все помещения, Кухня, Ванная, Туалет, Прихожая, Гостиная, Спальни, Балкон/Лоджия)
* Требуются демонтажные работы (чекбокс)
* Требуется дозакупка материалов (Все материалы от компании / Частично от клиента / Все от клиента)
* Желаемая дата начала работ (датапикер)
* Срочность (Не срочно / В течение месяца / Срочно)
Блок 4: Процесс продажи
* Текущий этап воронки (автоматически по позиции карточки)
* Дата перехода на текущий этап (автоматическая)
* Дней на этапе (счетчик с цветовой индикацией: зеленый 0-3 дня, желтый 4-7 дней, красный 8+ дней)
* Запланированные задачи (список с дедлайнами: позвонить, отправить КП, записать на замер)
* История перемещений по этапам (таймлайн с датами и ответственными)
* Комментарии и примечания (timeline с возможностью @упоминаний коллег)
* Прикрепленные файлы (фото объекта, старый дизайн-проект клиента, референсы)
Блок 5: Связанные сущности и документы
* ID связанной сметы/проекта (ссылка на раздел "Проекты", null если смета не создана)
* ID объекта (ссылка на раздел "Объекты", null до подписания договора)
* Выезд замерщика (дата, время, назначенный сотрудник)
* Результаты замера (файлы: чертежи, фото, записи)
* Коммерческое предложение (генерируемый PDF, дата отправки, статус просмотра)
* Договор (загруженный файл, дата подписания, статус)
* Счет на предоплату (сумма, статус оплаты, дата)
Настройки воронки продаж
Таблица "Этапы воронки" (Pipeline Stages)
Хранит информацию о каждом этапе:
* ID этапа (UUID)
* Название (текст, редактируемое)
* Порядковый номер (integer, определяет последовательность)
* Цвет (hex-код для визуальной идентификации)
* Тип этапа (enum: active, won, lost, system)
* Является ли дефолтным (boolean, защита от удаления)
* Средний срок нахождения на этапе (дней, для аналитики)
* Конверсия в следующий этап (%, рассчитывается автоматически)
* Автоматические действия (JSON с триггерами: отправить email, создать задачу, уведомить в Telegram)
Дефолтная конфигурация воронки
При первом запуске создаются 8 этапов:[firstbit]​[ppl-ai-file-upload.s3.amazonaws]​
1. Квалифицировать (синий #3B82F6)
   * Тип: active
   * Средний срок: 1-2 дня
   * Действия: первичный контакт, выявление потребностей, оценка платежеспособности
   * Автоматика: создать задачу "Позвонить клиенту" с дедлайном +2 часа
2. Записать на замер (голубой #06B6D4)
   * Тип: active
   * Средний срок: 2-3 дня
   * Действия: согласование даты/времени выезда, назначение замерщика
   * Автоматика: отправить SMS с подтверждением времени визита, создать событие в календаре замерщика
3. Провести замер (бирюзовый #14B8A6)
   * Тип: active
   * Средний срок: 1 день (день замера)
   * Действия: выезд замерщика, фиксация параметров, фото объекта
   * Автоматика: активировать кнопку "Создать смету" после отметки "Замер проведен"
4. Подготовить смету (зеленый #10B981)
   * Тип: active
   * Средний срок: 2-5 дней
   * Действия: расчет сметы с помощью AI в разделе "Проекты", согласование с прорабом
   * Автоматика: уведомление менеджеру когда смета готова
5. Презентовать КП (желто-зеленый #84CC16)
   * Тип: active
   * Средний срок: 1-3 дня
   * Действия: отправка КП клиенту, презентация по телефону/встрече
   * Автоматика: генерация красивого PDF с КП, трекинг открытия письма
6. Дожать в договор (оранжевый #F59E0B)
   * Тип: active
   * Средний срок: 3-7 дней
   * Действия: работа с возражениями, предоставление скидок/бонусов, повторная отправка КП
   * Автоматика: создать задачу "Follow-up звонок" через 2 дня если нет движения
7. Договор подписан (темно-зеленый #059669)
   * Тип: won (критический этап)
   * Средний срок: 1 день
   * Действия: подписание договора, получение предоплаты, переход в производство
   * Автоматика критическая:
      * Создать карточку объекта в разделе "Объекты"
      * Перенести все данные сделки в карточку объекта
      * Связать смету из "Проектов" с объектом
      * Уведомить производственный отдел в Telegram
      * Поменять статус сделки на "Реализована"
      * Отправить welcome-письмо клиенту с доступом к клиентскому порталу
8. Нереализованные (серый #6B7280)
   * Тип: lost (архивный этап)
   * Действия: фиксация причины отказа, планирование повторного контакта
   * Автоматика: создать задачу "Повторный контакт" через 3 месяца
Интерфейс настройки воронки
Доступен только администраторам и владельцам организации:[ppl-ai-file-upload.s3.amazonaws]​
Режим редактирования этапов:
* Drag & drop для изменения порядка этапов
* Кнопка "Добавить этап" с формой:
   * Название (текст, макс 50 символов)
   * Выбор цвета (палитра)
   * Тип этапа (активный/выигранный/проигранный)
   * Настройка автоматических действий (конструктор триггеров)
* Для каждого этапа три действия: ⚙️ Редактировать / 🗑️ Удалить / 📊 Статистика
* Дефолтные этапы имеют замок 🔒 и не могут быть удалены, только переименованы
* Кнопка "Сбросить до дефолта" возвращает стандартную конфигурацию
Настройка автоматизаций:
* При входе на этап: создать задачу, отправить уведомление, изменить поле
* При истечении времени на этапе: уведомить менеджера, передать другому ответственному
* При выходе с этапа: запросить причину (для этапа "Нереализованные")
Источники сделок
Таблица "Источники" (Deal Sources)
* ID источника (UUID)
* Название (текст: Сайт, Телеграм, Телефония, Email, etc.)
* Иконка (emoji или SVG)
* Активен (boolean, можно деактивировать источник)
* Стоимость лида (₽, для расчета ROI)
* Количество лидов (счетчик)
* Конверсия в сделку (%, автоматический расчет)
* Средний чек (₽, по закрытым сделкам из этого источника)
Дефолтные источники при инициализации
1. 🌐 Сайт (автоматический захват через веб-формы)
2. ✈️ Телеграм (интеграция с ботом)
3. 📧 Email (парсинг писем на корпоративную почту)
4. ☎️ Телефония (интеграция с IP-телефонией)
5. 📱 Instagram (заявки из директа)
6. 👥 Рекомендации (реферальная программа)
7. 🔄 Повторное обращение (клиенты из архива)
8. 🎯 Контекстная реклама (Яндекс.Директ, Google Ads)
9. ❓ Другое (неопределенный источник)
Интерфейс управления источниками:
* Список всех источников с метриками
* Добавление нового источника (форма: название, иконка, стоимость лида)
* Деактивация источника (не удаляется, чтобы сохранить историю)
* Экспорт отчета по эффективности источников
Пользовательский интерфейс
Основной вид: Kanban-доска
Структура доски
Шапка страницы:
* Название "Продажи" (H1)
* Кнопка "+ Новая сделка" (primary action, синяя)
* Кнопка "⚙️ Настройки воронки" (для админов)
* Фильтры:
   * По ответственному менеджеру (мультивыбор)
   * По источнику (мультивыбор)
   * По температуре лида (горячий/теплый/холодный)
   * По диапазону бюджета (слайдер)
   * По дате создания (датапикер)
* Кнопка "Сбросить фильтры"
* Переключатель вида: 📊 Kanban / 📋 Таблица / 📈 Аналитика
Область колонок (горизонтальный скролл):
* Каждая колонка = этап воронки[housecallpro]​
* Заголовок колонки:
   * Название этапа
   * Счетчик сделок (например, "7")
   * Общая сумма бюджетов на этапе (например, "2.4M ₽")
   * Средний срок на этапе (например, "3.5 дня")
   * Кнопка меню (⋮) с действиями: Посмотреть статистику, Массовые действия
* Цветная полоса под заголовком (цвет этапа)
* Карточки сделок внутри (drag & drop)
Карточка сделки на доске (компактный вид)
Размер: 280px ширина × ~160px высота
Содержимое:
text
┌─────────────────────────────────────────┐
│ 🔥 [Имя Клиента]              [⋮]       │ <- Температура + меню
│ [Телефон] ☎️ 💬                          │ <- Кнопки быстрых действий
│                                         │
│ 📍 [Адрес, первые 30 символов...]      │
│ 🏠 [Тип ремонта] • [Площадь]м²         │
│ 💰 [Бюджет] ₽                          │
│                                         │
│ [Источник] • [X дней на этапе]         │ <- С цветовой индикацией
│                                         │
│ 👤 [Менеджер]  📊 [Кнопка сметы]       │ <- Аватар + действие
└─────────────────────────────────────────┘


Цветовые индикаторы:
* Левая граница карточки: цвет по температуре лида
* Значок дней на этапе: зеленый (0-3), желтый (4-7), красный (8+)
* Просрочные задачи: красная точка в правом верхнем углу
Интерактивность:
* Клик по карточке → открытие модального окна с полной информацией
* Drag карточки → перемещение между этапами (с подтверждением критических переходов)
* Клик по кнопке сметы → открытие связанного проекта или форма создания
* Клик по иконке телефона → инициация звонка (если есть интеграция телефонии)
* Клик по иконке чата → открытие Telegram/WhatsApp
Модальное окно карточки сделки (полный вид)
Открывается поверх доски, ширина 800px, прокручиваемое.[ppl-ai-file-upload.s3.amazonaws]​
Структура модального окна:
Шапка модалки:
* Бейдж с текущим этапом (цветной)

* Кнопка "✕ Закрыть" (правый верх)
* Кнопка "🗑️ Удалить сделку" (деструктивное действие, с подтверждением)

async function saveProject(projectData, dealId) {
  // Создаем проект
  const project = await createProject(projectData);
  
  // Связываем с сделкой
  if (dealId) {
    await updateDeal(dealId, {
      project_id: project.id,
      project_created_at: new Date()
    });

    await addDealTimelineEvent(dealId, {
      type: 'project_created',
      message: `Создана смета/проект #${project.id}`,
      user_id: currentUser.id
    });
  }
  
  return project;
}

Интеграция с Telegram
Уведомления (отправляются автоматически):
         * Новая сделка создана → ответственному менеджеру
         * Сделка не двигается 7+ дней → менеджеру + руководителю
         * Клиент просмотрел КП → менеджеру (если есть email tracking)
         * Договор подписан → всей команде + производственному отделу
         * Задача просрочена → ответственному
Управление сделками из Telegram бота:
Менеджер может в боте написать:
text
/mysales - мои активные сделки (список с кратким статусом)
/deal 40920047 - информация по конкретной сделке
/comment 40920047 Клиент попросил перезвонить завтра - добавить комментарий
/stage 40920047 5 - переместить сделку на этап #5


Двусторонняя синхронизация:[ppl-ai-file-upload.s3.amazonaws]​
         * Сообщения из Telegram-бота с клиентом сохраняются в timeline сделки
         * Комментарии из карточки сделки можно отправлять в Telegram-чат с клиентом
         * Кнопка "Написать в Telegram" в карточке сделки открывает чат в Telegram Web
Интеграция с телефонией
Если подключена IP-телефония (например, Asterisk, Zadarma):
Входящий звонок:
         1. Определяется номер телефона звонящего
         2. Поиск в БД сделок по номеру
         3. Если сделка найдена:
         * Всплывающее окно с карточкой сделки (screen pop)
         * Возможность сразу добавить комментарий о звонке
         4. Если сделка не найдена:
         * Всплывающее окно "Создать новую сделку" с предзаполненным телефоном
         5. После завершения звонка:
         * Автоматическое добавление записи в timeline: "📞 Входящий звонок, длительность X мин"
         * Если есть запись разговора → ссылка на аудиофайл
Исходящий звонок:
         * Клик по кнопке телефона в карточке → инициация звонка через WebRTC или CTI-интеграцию
         * Автоматическое логирование исходящих звонков
Интеграция с Email
Отправка КП клиенту:
         1. Генерация PDF с коммерческим предложением (используется смета из раздела "Проекты")
         2. Email-форма с:
         * Поле "Кому": email клиента (из карточки)
         * Тема (шаблон): "Коммерческое предложение на ремонт по адресу [адрес]"
         * Тело письма (редактируемый шаблон с переменными)
         * Прикрепленный PDF
         3. Опция "Отследить открытие письма" (вставка tracking pixel)
         4. После отправки:
         * Запись в timeline: "✉️ КП отправлено на [email]"
         * Если письмо открыто → уведомление менеджеру + запись в timeline
Входящие письма:
         * Парсинг заявок с корпоративной почты (например, info@company.ru)
         * Автоматическое создание сделки из письма:
         * ФИО из подписи/темы
         * Email из "From"
         * Телефон из текста (regex извлечение)
         * Текст письма → первый комментарий
         * Вложения → файлы сделки
Права доступа и роли[ppl-ai-file-upload.s3.amazonaws]​
Роль: Admin / Владелец организации
Полный доступ ко всему функционалу:
         * ✅ Просмотр всех сделок организации
         * ✅ Редактирование всех сделок
         * ✅ Настройка воронки продаж (добавление/удаление/редактирование этапов)
         * ✅ Настройка источников сделок
         * ✅ Массовые действия со сделками
         * ✅ Удаление сделок
         * ✅ Просмотр полной аналитики по всем менеджерам
         * ✅ Изменение ответственных менеджеров
         * ✅ Настройка автоматизаций и уведомлений
Роль: Manager (менеджер по продажам)
Основной пользователь раздела:
         * ✅ Просмотр только своих сделок (где он ответственный)
         * ✅ Создание новых сделок
         * ✅ Редактирование своих сделок (все поля)
         * ✅ Перемещение своих сделок по этапам
         * ✅ Добавление комментариев и файлов
         * ✅ Назначение замерщиков
         * ✅ Создание смет (переход в раздел "Проекты")
         * ✅ Закрытие своих сделок
         * ✅ Просмотр чужих сделок (read-only, для обучения) - опция настраивается админом
         * ❌ Удаление сделок
         * ❌ Изменение ответственного менеджера
         * ❌ Настройка воронки
         * ✅ Просмотр аналитики только по своим сделкам
Роль: Measurer (замерщик)
Ограниченный доступ:
         * ✅ Просмотр сделок на этапах "Записать на замер" и "Провести замер" где он назначен
         * ✅ Редактирование полей связанных с замером:
         * Дата/время выезда
         * Результаты замера
         * Загрузка фото объекта
         * Загрузка чертежей
         * Отметка "Замер проведен"
         * ✅ Добавление комментариев
         * ✅ Создание сметы после проведения замера
         * ❌ Редактирование контактных данных клиента
         * ❌ Перемещение сделок по этапам
         * ❌ Просмотр других сделок
Роль: Foreman / Master (прораб, мастер)
Минимальный доступ:
         * ✅ Просмотр сделок на этапе "Договор подписан" (для подготовки к запуску объекта)
         * ✅ Просмотр связанных смет
         * ❌ Редактирование сделок
         * ❌ Основная работа в разделе "Объекты", а не "Продажи"
Роль: Client (клиент)
Нет доступа к разделу "Продажи":
         * ❌ Клиенты не видят раздел "Продажи"
         * ✅ Клиенты работают через отдельный "Клиентский портал" где видят:
         * Статус своей заявки (упрощенный view)
         * Смету (если она готова)
         * Объект (если договор подписан)
Оптимизации и UX-детали
Быстрые действия
Клавиатурные сокращения:
         * Ctrl+N - создать новую сделку
         * Ctrl+F - фокус на поиск
         * Esc - закрыть модальное окно
         * Ctrl+S - сохранить изменения
         * → / ← - переключение между табами в модалке
Inline-редактирование на Kanban-доске:
         * Двойной клик по ФИО → редактирование имени без открытия модалки
         * Клик по температуре лида → переключение 🔥→🌡️→❄️
         * Клик по иконке источника → смена источника (dropdown)
Контекстное меню (правый клик по карточке):
         * Открыть полностью
         * Позвонить клиенту
         * Написать в Telegram
         * Открыть смету
         * Изменить этап
         * Создать задачу
         * Удалить
Производительность
Ленивая загрузка:
         * На Kanban-доске изначально загружается только 50 карточек
         * При скролле вниз подгружаются еще 50 (infinite scroll)
         * Фильтры работают на бэкенде, а не фронте
Оптимистичные обновления:
         * При перемещении карточки она мгновенно меняет позицию (без ожидания ответа сервера)
         * Если сервер вернет ошибку → карточка вернется на место + показать тост с ошибкой
Кэширование:
         * Список этапов воронки кэшируется в localStorage (обновляется раз в день)
         * Список источников кэшируется
         * Данные пользователей организации кэшируются
Адаптивность
Мобильная версия (viewport < 768px):
         * Kanban-доска заменяется на вертикальный список (одна колонка)
         * Фильтр по текущему этапу (tabs вверху экрана)
         * Карточки сделок занимают полную ширину
         * Модальное окно на 100% высоты экрана
         * Упрощенная форма создания сделки (только ФИО, телефон, источник)
         * Swipe-жесты: свайп влево → открыть меню действий, свайп вправо → закрыть
Планшетная версия (768px - 1024px):
         * Kanban с 3-4 колонками видимыми одновременно
         * Горизонтальный скролл для остальных колонок
         * Модальное окно 80% ширины экрана
Уведомления и индикаторы
Визуальные индикаторы на карточках:
         * 🔴 Красная точка = есть просроченная задача
         * 🔵 Синяя точка = непрочитанный комментарий от коллеги
         * 📧 Иконка письма = КП отправлено, но не открыто
         * ✅ Зеленая галочка = КП открыто клиентом
         * ⏰ Иконка часов = приближается дедлайн задачи (завтра или сегодня)
Browser-уведомления (Web Push):
         * Новая сделка назначена на вас
         * Клиент открыл ваше КП
         * Сделка не двигается 7 дней
         * Задача просрочена
         * Коллега упомянул вас в комментарии
Звуковые уведомления:
         * Входящий звонок (если интеграция телефонии)
         * Новая сделка (опция включается в настройках)

Заключение
Раздел "Продажи" спроектирован как центральный hub управления клиентским циклом от первого касания до передачи в производство. Ключевые принципы:
         1. Визуальность: Kanban-доска дает мгновенное понимание статуса всех сделок
         2. Автоматизация: критические переходы (замер→смета, договор→объект) автоматизированы
         3. Интеграция: бесшовная связь с разделами "Проекты" и "Объекты" через двусторонние ссылки
         4. Гибкость: настраиваемая воронка под специфику бизнеса
         5. Аналитика: встроенные метрики для принятия решений
         6. Коммуникация: Telegram-интеграция для работы в движении
Архитектура поддерживает масштабирование от одного менеджера до крупной команды с разграничением прав доступа.[ppl-ai-file-upload.s3.amazonaws]​
